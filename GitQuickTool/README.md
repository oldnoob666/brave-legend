# 本 Unity 项目的 SourceGit

根据用户选择，直接采用现成的 SourceGit 中文版，保留源码供后续修改。本目录不是自行开发完成的 WPF Git GUI。

## 打开程序

双击本目录的 **打开本项目 Git.lnk**，会直接打开 `D:\unity01\My project (2)`。

也可以运行 `tools/SourceGit-2026.19/SourceGit/SourceGit.exe`，通过左上方打开仓库按钮选择项目根目录。不要选择 `Assets/` 或 `.git/`。

- 官方项目：https://github.com/sourcegit-scm/sourcegit
- 固定版本：v2026.19（2026-08-31 发布）
- 官方发行页：https://github.com/sourcegit-scm/sourcegit/releases/tag/v2026.19
- 许可证：MIT，原始 LICENSE 随源码及程序保留。
- 技术：C# + Avalonia；此版本源码目标为 .NET 10，非 WPF/.NET 8。
- 本次下载 Windows x64 官方便携版，已核对 GitHub 资产提供的 SHA-256。
- Git 需单独安装，本机已有 Git 2.45.1；其他电脑从 https://git-scm.com/downloads/win 安装 Git for Windows，安装后重启 SourceGit。
- 官方发行包可直接运行，不需要先编译源码。若修改并编译源码，需另外安装 .NET 10 SDK，并按上游构建说明安装对应工具；本机当前 SDK 为 9.0.317，不能直接编译此源码目标。

## 日常操作

1. 在 Unity 保存脚本、场景和资源，等待导入结束。
2. 打开 SourceGit，选择左侧 **本地更改**。
3. 在 **未暂存** 列表点击文件，查看右侧 Diff。Ctrl/Shift 可多选。
4. 右键文件选择 **暂存(add)**，或点击 **暂存所有**。新增、移动、删除 Unity 资源时，检查相关 `.meta` 一起进入暂存区。
5. 检查 **已暂存** 列表；误选的文件可右键 **从暂存中移除**，也可使用 **从暂存区移除所有** 按钮。
6. 在右下方填写提交信息，点击 **提交**。第一次练习可用本次新增的说明文件，不需要改游戏内容。
7. 需要上传时使用顶部 **推送**。本项目当前未配置远程，所以现阶段在 Commit 完成后即可停止。

不要随意勾选“修补”（改写最近一次提交）或“跳过 GIT 钩子”。保存 Unity 文件不会自动提交。

## 其他主要入口

| 功能 | SourceGit 入口 |
| --- | --- |
| 配置本仓库姓名和邮箱 | 左上工具栏齿轮，提示为“配置本仓库” |
| 查看提交、作者、时间、文件和 Diff | 左侧“历史记录”，选择提交 |
| 复制提交哈希、回滚提交 | 历史记录中右键提交 |
| 创建、切换、删除、合并分支 | 左侧“本地分支”的新增按钮或分支右键菜单 |
| 查看、添加、修改、删除远程 | 左侧“远程列表”和右键菜单 |
| Fetch / Pull / Push | 顶部工具栏，悬停图标查看名称 |
| Stash | 顶部贮藏操作及左侧“贮藏列表”，右键条目应用或删除 |
| 比较两个提交 | 历史记录多选两个提交，查看比较结果 |
| 原始命令和输出 | 左上工具栏“查看命令日志” |
| 恢复文件 | 文件右键“丢弃更改”；语义及风险见下文 |

Fetch 获取远程信息；Pull 获取并整合远程修改；Push 上传本地提交。首次远程操作先在“远程列表”添加你拥有权限的仓库 URL，再选择目标分支／跟踪分支。远程登录由 Git 凭据管理器处理，不要把密码写进 URL。

## Unity 和恢复操作

现有 `.gitignore` 已保留。SourceGit 使用 Git 自身的忽略规则；没有为此项目自动覆盖任何规则。对本项目已核对 Library、Temp、obj、Logs、UserSettings 被忽略，且无已跟踪缓存。

切换分支、回滚或恢复场景前先保存并关闭 Unity。恢复资源需要同时考虑 `.meta`，否则可能出现丢失引用。

**“丢弃更改”会丢失未提交内容；不要把它当成“取消暂存”。** SourceGit 对未跟踪文件的丢弃还可能直接删除文件。它的指定文件丢弃只恢复工作区；若要对应指南的“恢复到 HEAD，同时清除暂存”，先对已暂存的目标文件取消暂存，再对它丢弃工作区修改。确认文件名和相关 `.meta`，不确定时先复制备份。

SourceGit 的确认框和命令日志遵循上游产品设计，没有补做最初要求的统一命令预览、两次确认、禁止空提交、自动 `.meta` 配对或 Unity 专项检查按钮。当前版本是用户选定的现成工具方案，不宣称它逐条满足原定制程序规格。详细对照见 `Docs/SourceGit功能对照.md`。

## 常见问题

- **看不到修改**：先保存 Unity；确认选择了正确仓库，且文件没有被忽略。工具和源码下载目录已忽略，不会出现在待提交列表。
- **提交按钮不可用**：先暂存文件并填写提交信息。没有更改时无需提交。
- **找不到 Git**：安装 Git for Windows，或在 SourceGit 首选项选择 `git.exe`。
- **无法推送／没有远程**：本项目目前只有本地仓库；先添加远程及设置对应分支。有权限错误时核对账号及凭据；不要强制推送来处理权限问题。
- **远程有本地没有的提交**：先 Fetch 查看差异，再决定 Pull 整合；有冲突时先人工解决、暂存、完成提交。
- **冲突**：在“本地更改”查看冲突文件，使用编辑器或配置的合并工具解决。不要不加检查地选择“使用本地/远程版本”。
- **移动了项目目录**：快捷方式使用绝对路径，移动后直接打开 EXE 并重新选择仓库，或重建快捷方式。
- **换电脑／备份**：源码与便携包不纳入 Unity 仓库提交。需要保留本地程序配置时复制整个本目录；项目提交历史位于根目录 `.git/`，异盘备份也要保留它。

## 文件布局和修改源码

```text
GitQuickTool/
  打开本项目 Git.lnk
  README.md
  Docs/SourceGit功能对照.md
  Docs/SourceGit下载记录.json
  vendor/release-source/sourcegit-2026.19/   原始源码及 LICENSE
    src/Commands/                         Git 执行层
    src/ViewModels/                        工作流和状态
    src/Views/                             Avalonia 界面
    src/Models/                            数据模型
    depends/AvaloniaEdit/                  固定提交的依赖源码
  tools/SourceGit-2026.19/SourceGit/         官方可运行程序及 DLL
    data/preference.json                  中文设置和最近仓库
  tools/*.zip                             原始下载包
```

源码来自 tag 压缩包，依赖来自固定 commit 压缩包；不是完整 Git 历史克隆。上游 Git clone 在本次网络环境中未完成，已改用 GitHub 源码归档。需要完整上游历史时另外执行 `git clone --recurse-submodules https://github.com/sourcegit-scm/sourcegit.git`。

当前修改源码不会改变已经下载的 EXE，必须按上游流程重新编译。源码、发布包和运行配置由本目录 `.gitignore` 排除，防止大量第三方内容进入 Unity 提交；版本、下载链接及校验值单独记录，便于重现。
